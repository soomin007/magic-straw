# 작업 방식

이 문서는 사용자, Claude Code, Codex가 이 프로젝트를 어떻게 나눠 맡고, 어떤 순서로 주고받는지 정한다.
랩탑과 데스크탑 두 컴퓨터에서 번갈아 작업할 때 지킬 순서도 여기에 있다.
`CLAUDE.md`와 `AGENTS.md`는 이 문서를 따르고, 셋이 서로 다르면 이 문서를 고친 뒤 나머지를 맞춘다.

## 역할

| 누가 | 맡는 일 | 하지 않는 일 |
|---|---|---|
| 사용자 | 게임의 방향, 시점, 그림체를 정한다. 목업과 그림을 승인하고 직접 플레이해서 의견을 낸다. 어느 에이전트에게 무엇을 맡길지 정한다 | |
| Claude Code | 설계 문서, 규칙 엔진, 레벨, 화면 코드, 검증 도구, 목업, 그림 목록과 의뢰서를 만든다. Codex가 만든 파일을 검토하고, 공개해도 되는 것만 골라 커밋하고 push한 뒤 배포를 확인한다 | 그림 파일을 직접 생성하지 않는다(이미지 생성 기능이 없다) |
| Codex | `assets/asset-list.js`의 그림을 만들고 `assets/manifest.js`에 등록한 뒤 `docs/art-check.html`로 확인한다. 요청을 받으면 저장소를 검토하고 기록을 남긴다 | `src/`, 레벨, 설계 문서, 목업을 고치지 않는다. 커밋하거나 push하지 않는다 |

Codex의 실행 환경(샌드박스)은 `.git` 폴더 쓰기를 보안상 막아 두었다. 이 제한은 풀지 않는다.
그래서 Codex는 작업한 파일을 커밋하지 않은 채로 두고, Claude Code가 검토한 뒤 커밋한다.
Codex는 `.git` 쓰기 권한을 요청하거나 커밋을 다시 시도하지 않는다.

## 한 바퀴의 흐름

작업은 아래 순서로 한 바퀴씩 돈다. 한 바퀴가 끝날 때마다 게임 주소(https://soomin007.github.io/magic-straw/)에 최신 상태가 올라간다.

1. 사용자가 방향을 정한다. 시점, 그림체, 화면 구성, 첫 진입 흐름처럼 되돌리기 비싼 결정은 Claude Code가 회색 상자 목업으로 먼저 보여 주고 확인받는다.
2. Claude Code가 규칙, 레벨, 화면을 만들고 검증 도구를 통과시킨다. 그림이 필요하면 `assets/asset-list.js`와 `docs/art-brief.md`를 고친다. 커밋하고 push한다.
3. 사용자가 Codex에게 그림을 맡긴다. Codex는 그림을 만들어 등록하고, 세션 로그의 "커밋 대기" 목록에 바꾼 파일을 적은 다음 멈춘다.
4. 사용자가 Claude Code에게 "Codex 작업 검토하고 올려 줘"라고 말한다. Claude Code는 그림을 확인 페이지와 실제 화면에서 보고, 로컬 경로나 개인 정보 같은 공개하면 안 되는 내용을 걸러서 커밋하고 push한다. 고쳐야 할 그림이 있으면 목록으로 정리해 사용자에게 알린다.
5. 사용자가 플레이해 보고 의견을 낸다. 다음 바퀴의 1번으로 돌아간다.

같은 폴더에서는 한 번에 한 에이전트만 파일을 고친다. Codex가 작업하는 동안 Claude Code는 파일을 읽기만 하고, 고치거나 커밋하지 않는다.
반대로 Claude Code가 작업하는 동안에는 Codex를 돌리지 않는다.

## 공개 저장소에 올리지 않는 것

이 저장소는 공개 저장소라서 누구나 볼 수 있다. 다음 내용은 파일에 쓰지 않거나, 커밋하기 전에 지운다.

- 컴퓨터 안의 절대 경로 (`C:\Users\...` 같은 원본 파일 위치). 저장소 안의 파일은 저장소 기준 상대 경로로 적는다
- 이메일, 비밀번호, API 키 같은 개인 정보와 비밀 값
- 이미지 파일에 들어간 생성 정보 같은 텍스트 메타데이터

Codex는 `assets/generation.json`에 그림마다 생성 지시문을 남기되, 원본 이미지의 로컬 경로는 적지 않는다.

## 두 컴퓨터에서 작업하기

저장소의 기준은 GitHub(https://github.com/soomin007/magic-straw)이다. 한 컴퓨터에서 끝낸 작업은 반드시 push하고, 다른 컴퓨터에서는 시작하기 전에 받아 온다.
OneDrive 같은 동기화 폴더에는 저장소를 두지 않는다. 동기화 프로그램이 `.git` 폴더를 건드리면 저장소가 깨질 수 있다.

데스크탑에서 처음 작업할 때는 저장소를 한 번 복제한다. 데스크탑에서도 랩탑처럼 사용자 폴더 안의 `Dev` 폴더 아래에 둔다.
데스크탑 복제는 2026-10-24에 마쳤고, 그 자리에서 검증 도구와 로컬 미리보기가 그대로 동작하는 것을 확인했다.

```bash
git clone https://github.com/soomin007/magic-straw.git
```

그 뒤로는 어느 컴퓨터든 작업을 시작할 때 다음 순서를 지킨다.

1. `git pull`로 다른 컴퓨터에서 올린 작업을 받아 온다.
2. `CLAUDE.md`(Codex는 `AGENTS.md`), `known-issues.md`, 가장 최근의 `session_logs/` 파일을 읽는다.
3. `git status`로 커밋하지 않은 파일이 있는지 본다. 있으면 그 파일이 누구의 작업인지 세션 로그에서 확인하고, 모르면 사용자에게 묻는다.

작업을 마칠 때는 다음 순서를 지킨다.

1. 세션 로그에 요약, 주요 변경, 결정 사항, 다음 할 일을 남긴다. 같은 날짜 파일이 있으면 이어서 쓴다.
2. 바꾼 파일만 골라 커밋하고 push한다(`git add -A`를 쓰지 않는다).
3. 다른 컴퓨터로 옮기기 전에, push까지 끝났는지 `git status`와 `git log origin/main..`으로 확인한다.

두 컴퓨터에서 같은 날 작업해서 push가 거절되면 `git pull --rebase`로 받아 온 뒤 다시 push한다. 같은 파일을 양쪽에서 고쳐 충돌이 나면, 어느 쪽을 남길지 사용자에게 묻는다.

## 컴퓨터마다 따로 있는 것

다음은 GitHub로 옮겨지지 않는다. 다른 컴퓨터에서 이어서 작업할 때 필요한 맥락은 반드시 저장소 안의 문서(`CLAUDE.md`, `docs/`, `session_logs/`)에 적는다.

| 항목 | 위치 | 설명 |
|---|---|---|
| Claude 전역 지침 | 각 컴퓨터의 `~/.claude/CLAUDE.md` | 원본은 데스크탑에 있고, 랩탑에는 필요한 절만 옮겼다. 이 프로젝트에 필요한 규칙은 프로젝트 `CLAUDE.md`와 이 문서에 있으므로 어느 컴퓨터에서든 같게 적용된다 |
| Claude의 기억 | 각 컴퓨터의 Claude 설정 폴더 | 컴퓨터마다 따로 쌓인다. 기억에만 있는 결정은 다른 컴퓨터에서 알 수 없으니, 중요한 결정은 문서에 남긴다 |
| Codex가 생성한 원본 이미지 | 각 컴퓨터의 Codex 설정 폴더 | 저장소에는 크기를 맞춘 최종 PNG만 올린다 |
| Codex 첫 MVP 작업물 | 랩탑의 `Documents\Codex\2026-10-21\` | 참고용이고 저장소에는 없다 |
| 로컬 미리보기 서버 설정 | `.claude/launch.json` | Python의 `http.server`를 쓴다. Python이 없는 컴퓨터에서는 아무 정적 서버나 써도 된다 |

검증 도구는 Node.js가 있으면 `node tools/verify.js`로, 없으면 브라우저로 `tools/verify.html`을 열어 돌린다. 데스크탑에는 Node.js가 있고, 랩탑에는 없다.

## 나중에 할 일: 게임 허브 등록

데스크탑의 전역 지침에는 "새 게임을 웹에 배포하면 게임 허브(soomin007.github.io)에도 등록한다"는 루틴이 있다.
이 게임은 아직 만드는 중이라 등록하지 않았다. 사용자가 공개해도 된다고 하면, 허브 저장소가 있는 데스크탑에서 그 루틴대로 등록한다.
