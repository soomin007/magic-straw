# 프로젝트 검토 기록

2026년 10월 24일에 Codex가 현재 저장소의 규칙, 레벨, 목업, 그림 교체 구조를 검토했다. 검토 중 Claude Code의 화면 구현과 후속 수정이 들어와, 최종 기록은 커밋 `933a042`와 이번에 생성한 그림을 기준으로 갱신했다.

## 현재 구현 범위

이 프로젝트에는 규칙 엔진과 1챕터 여덟 판, 실제 플레이 화면이 있다. `src/game.js`와 `src/style.css`가 탑뷰, 숙이기 단면, 카메라, 프롤로그, 손가락 튜토리얼과 랩탑 배터리 연출을 맡는다. `src/assets.js`는 그림 이름을 실제 PNG에 연결하고, 아직 없는 그림은 회색 상자로 표시한다. `docs/mockup/index.html`은 방향을 확인받을 때 사용한 목업으로 남아 있다.

검토자는 최신 `tools/verify.js`를 실행해 48개 검사가 모두 통과하는 것을 확인했다. 여덟 판의 최소 행동 수는 순서대로 1, 2, 1, 2, 2, 3, 2, 4였다. 앞의 여섯 판은 탑뷰만으로 같은 최소 행동 수에 풀리고, 마지막 두 판은 높이 조준이 있어야 풀린다. 검토자는 브라우저에서 여유 난이도의 여덟 판을 이 행동 수로 직접 풀었고, 마지막 판의 되돌리기와 카메라 열기 및 닫기도 확인했다. 검토자는 해법을 알고 있었으므로, 이 결과가 처음 플레이하는 사람의 이해도나 게임의 재미를 입증하지는 않는다.

## 구조와 설계에 대한 판단

규칙 엔진은 원래 상태를 복제한 뒤 행동을 적용하고, 연출에 필요한 얼음 경로와 효과 직후 상태를 별도로 돌려준다. 따라서 화면 코드가 퍼즐의 규칙을 다시 구현할 필요가 없다. 레벨은 읽을 수 있는 지도와 최소 행동 수를 함께 저장하며, 검증 도구가 실제 해법을 탐색한다. 현재 구조는 그림을 교체하면서 규칙을 유지하기에 적절하다.

레벨은 얼음으로 밀기, 거품으로 띄우기, 메뉴판에서 꺾기, 상대 플러그 빼기, 행동 순서, 높이 조준을 차례로 소개한다. 사용자가 원했던 사물의 상태 변화와 순서를 중심으로 퍼즐을 구성했다. 얼음 조준선은 메뉴판에서 꺾이는 경로까지 보여 주고, 거품은 물건의 확대와 위치 변화로 뜬 상태를 표현한다. 실제 사람이 거품의 남은 수명과 높이 차이를 읽을 수 있는지는 별도 플레이 테스트로 확인해야 한다.

## 후속 작업자가 인지할 부분

처음 검토 때 그림 의뢰서의 묶음 설명과 레벨 요구 조건이 달랐지만, Claude Code가 `933a042`에서 문서를 바로잡았다. 현재 1차 그림 17개로 탑뷰 장면을 볼 수 있고, 레벨 7과 8의 숙인 시점은 2차 그림이 준비될 때까지 회색 상자로 표시된다.

처음 검토 때 엔진은 숙이기 도구의 해금 여부를 검사하지 않았지만, Claude Code가 같은 커밋에서 `check()`에 제한과 자동 검사를 추가했다. 최신 엔진은 숙이기를 쓸 수 없는 판에서 높이 조준을 거절한다. Codex는 이 수정이나 화면 구현을 하지 않았다.

첫 판의 튜토리얼에는 확인이 필요한 동작이 있다. 첫 진입에서 아이스 아메리카노를 고르고 아직 판 위로 포인터를 옮기지 않으면, 손가락이 내 플러그가 있는 가운데 줄이 아니라 빈 첫째 줄을 가리켰다. `src/game.js`의 `updateTutorial()`이 목표 플러그의 줄 대신 `game.focusRow`를 사용한다. 포인터를 움직이면 가리키는 줄도 바뀌므로, 다음 줄을 지정하는 안내인지 마우스가 있는 줄을 따라가는 표시인지 처음 플레이하는 사람이 혼동할 수 있다. 그림 작업 범위에 맞춰 Codex는 화면 코드를 고치지 않았다.

거품 PNG는 생성하고 등록했지만, 현재 플레이 화면은 이를 읽지 않는다. `shootBubble()`의 발사체와 `.piece-bubble`은 CSS 도형을 쓰고, `fx-ice`만 PNG를 읽는다. 따라서 그림 확인 페이지에서는 민트색 거품을 볼 수 있지만 플레이 중에는 파란 CSS 거품이 보인다. 후속 화면 작업자가 `fx-bubble` 연결 여부를 결정해야 한다.

`docs/art-check.html`은 6번 판을 한 장면으로 조립한다. 그 판에 없는 컵, 책, 음료 버튼과 효과는 개별 카드에서 확인해야 한다. 멀티탭 두 구간은 실제로 위아래를 이어 보고, 반투명 거품은 다른 물건 위에 겹쳐 봐야 한다.

## 그림 작업의 범위

Codex는 내장 image_gen으로 `assets/asset-list.js`의 1차 그림 17개를 각각 생성했다. 각 파일은 지정된 크기의 별도 투명 PNG이며, 서로 다른 물건이나 바닥 그림자를 한 파일에 합치지 않았다. 테이블에는 물건을 그리지 않았다. 내 물건은 민트색, 옆자리 사람의 물건은 벽돌색으로 구분했다. 두 플러그는 같은 모양을 공유하고, 메뉴판의 반대 기울기는 화면 코드가 좌우 반전해 쓴다.

Codex는 17개를 `assets/manifest.js`에 등록하고 그림 확인 페이지와 실제 플레이 화면에서 불러오는 것을 확인했다. 파일 검사는 17개 모두 지정 크기, RGBA, 투명 바깥 영역, 개별 경로 조건을 통과했고, 거품 중앙의 알파값도 0이었다. 멀티탭은 두 조각의 폭을 맞추고 위아래 끝을 열어 이어 붙였다. 생성 지시문은 `assets/generation.json`에 남겼으며, 생성 후에는 투명 여백 정리와 크기 변환만 수행했다.

이번 그림은 사용자가 검토할 1차 묶음이다. 굵은 외곽선과 색 구분은 공유하지만, 일부 면에는 의뢰서가 요구한 완전한 단색보다 부드러운 톤 변화가 남아 있다. 멀티탭 이음새에도 약한 색 차이가 보인다. 다음 묶음 전에 이 그림체를 검토하고, 필요하면 단색 처리를 더 강하게 요구해 조정해야 한다. 옆면 그림 10개와 프롤로그 다섯 컷은 아직 만들지 않았다. Codex는 이번 작업에서 `src/`, 레벨, 화면 목업을 수정하지 않았다.
