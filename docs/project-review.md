# 프로젝트 검토 기록

2026년 10월 24일에 Codex가 현재 저장소의 규칙, 레벨, 목업, 그림 교체 구조를 검토했다.

## 현재 구현 범위

이 프로젝트에는 규칙 엔진과 1챕터 여덟 판이 있다. `index.html`은 작업 중임을 알리는 페이지이고, `docs/mockup/index.html`은 탑뷰, 숙이기, 휴대폰 카메라 배치를 보여 주는 목업이다. 현재 작업 트리에는 실제 플레이 화면과 입력을 연결하는 코드가 없다. 이전 커밋에 있는 랩탑 연출을 새 화면에 연결하는 일도 남아 있다.

검토자는 `tools/verify.js`를 실행해 47개 검사가 모두 통과하는 것을 확인했다. 여덟 판의 최소 행동 수는 순서대로 1, 2, 1, 2, 2, 3, 2, 4였다. 앞의 여섯 판은 탑뷰만으로 같은 최소 행동 수에 풀리고, 마지막 두 판은 높이 조준이 있어야 풀린다. 이 결과는 규칙의 정합성을 확인하며, 조작의 이해도나 게임의 재미를 입증하지는 않는다.

## 구조와 설계에 대한 판단

규칙 엔진은 원래 상태를 복제한 뒤 행동을 적용하고, 연출에 필요한 얼음 경로와 효과 직후 상태를 별도로 돌려준다. 따라서 화면 코드가 퍼즐의 규칙을 다시 구현할 필요가 없다. 레벨은 읽을 수 있는 지도와 최소 행동 수를 함께 저장하며, 검증 도구가 실제 해법을 탐색한다. 현재 구조는 그림을 교체하면서 규칙을 유지하기에 적절하다.

레벨은 얼음으로 밀기, 거품으로 띄우기, 메뉴판에서 꺾기, 상대 플러그 빼기, 행동 순서, 높이 조준을 차례로 소개한다. 사용자가 원했던 사물의 상태 변화와 순서를 중심으로 퍼즐을 구성했다. 다만 실제 화면이 없으므로, 거품의 남은 수명과 높이, 메뉴판의 반사 방향을 플레이어가 읽을 수 있는지는 아직 판단할 수 없다.

## 구현 전에 인지할 부분

그림 의뢰서는 1차 묶음만으로 1챕터를 플레이할 수 있다고 적었지만, 레벨 7과 8에는 숙인 시점에서의 높이 조준이 필요하다. 1차 탑뷰 그림 17개가 준비돼도 마지막 두 판을 완성하려면 2차 옆면 그림이나 회색 상자 표현이 필요하다. 그림 목록의 묶음 순서는 유지한다.

엔진의 `check()`는 음료 종류와 좌표 범위를 검사하지만, 그 판에서 숙이기 도구를 해금했는지는 검사하지 않는다. `possibleActions()`의 높이 제한도 호출자가 전달한다. 화면 구현자는 레벨의 `tools`를 읽어 탑뷰에서는 높이 0으로만 쏘게 하고, 숙이기가 해금된 판에서만 높이를 고르게 해야 한다. 이 검토에서는 규칙 코드를 수정하지 않는다.

현재 자동 검사는 레벨 해법과 주요 규칙을 다루며, 아직 없는 프롤로그, 튜토리얼, 되돌리기 입력, 휴대폰 카메라, 배터리 팝업의 실제 조작은 검사하지 않는다. 검토자는 목업의 세 시점을 확인할 수 있지만, 실제 플레이 테스트가 끝났다고 보고하지 않는다.

`docs/art-check.html`은 6번 판을 한 장면으로 조립한다. 그 판에 없는 컵, 책, 음료 버튼과 효과는 개별 카드에서 확인해야 한다. 멀티탭 두 구간은 실제로 위아래를 이어 보고, 반투명 거품은 다른 물건 위에 겹쳐 봐야 한다.

## 그림 작업의 범위

Codex는 `assets/asset-list.js`에 기록된 1차 묶음 17개를 먼저 만든다. 각 파일은 지정된 크기의 별도 투명 PNG이며, 서로 다른 물건이나 바닥 그림자를 한 파일에 합치지 않는다. 테이블에는 물건을 그리지 않는다. 내 물건은 민트색, 옆자리 사람의 물건은 벽돌색으로 구분하고, 모든 그림은 굵은 검은 외곽선과 단색 면, 경계가 분명한 그림자 한 단계로 맞춘다.

Codex는 완성한 파일만 `assets/manifest.js`에 등록하고 그림 확인 페이지에서 실제 크기로 확인한다. Codex는 이번 그림 작업에서 `src/`와 레벨, 화면 목업을 수정하지 않는다. 옆면 그림 10개와 프롤로그 다섯 컷은 1차 묶음을 검토한 뒤 이어서 만들 수 있도록 남긴다.
