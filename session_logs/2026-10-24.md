### 주요 변경

- 코드는 OneDrive가 아니라 사용자 폴더 안의 `Dev` 폴더에 두고 GitHub로 동기화한다. OneDrive 동기화가 `.git` 폴더와 충돌하기 때문이다.

## 세션 2

### 요약
메타 연출 기기를 랩탑으로 정하고, 1챕터 여섯 판을 플레이할 수 있는 첫 프로토타입을 만들었다.
규칙 엔진과 검증 도구를 화면 코드와 분리했고, Codex에게 그림을 맡길 수 있도록 그림 의뢰서와 그림 교체 구조를 넣었다.

### 주요 변경
- `src/engine.js`: 옆에서 본 테이블 격자 규칙(얼음 밀기, 거품 띄우기와 터짐, 중력, 플러그 꽂기, 배터리, 난이도)
- `src/levels.js`: 1챕터 레벨 6개
- `tools/verify.js`, `tools/verify.html`: 레벨별 최소 행동 수 탐색과 규칙 단위 검사 (전부 통과)
- `index.html`, `src/game.js`, `src/style.css`, `src/art.js`: 랩탑 바탕화면 연출, 판 화면, 입력, 연출, SVG 그림
- `assets/manifest.js`: 그림 파일을 등록하면 SVG 대신 쓰는 목록
- `docs/design.md`, `docs/art-brief.md`, `AGENTS.md` 추가
- `known-issues.md`: 가려진 탭에서 애니메이션이 끝나지 않는 문제 추가

### 결정 사항
- 무대는 테이블을 옆에서 본 격자로 정했다. 위에서 본 격자에서는 소다의 "띄우기"가 그림으로 읽히지 않고, 옆에서 보면 띄우기와 떨어지기가 자연스럽게 보인다.
- 거품은 뱉은 다음 행동까지만 버틴다. 그래서 두 물건을 동시에 띄울 수 없고, 6번 판처럼 "유지할 상태"와 "잠깐 필요한 상태"를 나누는 퍼즐이 생긴다.
- 이 PC에는 Node.js가 없어서 검증 도구를 브라우저에서도 돌아가게 만들었다.
- Claude Code는 이미지를 생성할 수 없어서 그림은 SVG로 그렸고, 그림 파일은 Codex가 `docs/art-brief.md`대로 만들어 `assets/manifest.js`에 등록하는 방식으로 협업한다.
- 빠듯 난이도에서 판을 시작하자마자 절전 모드가 켜지던 문제를 고쳐, 한 번 이상 행동한 뒤에만 켜지게 했다.

### 미해결 / 다음 할 일
- 이 목록은 세션 3에서 방향이 바뀌며 대부분 바뀌었다. 세션 3의 목록을 따른다.

- 탑뷰에서는 줄끼리 영향을 주지 않아 퍼즐이 단조로워지는 문제가 있어, 얼음을 꺾는 삼각 메뉴판을 넣었다.
- 그림 목록은 코드가 읽는 `assets/asset-list.js` 하나로 관리하고, 의뢰서와 확인 페이지가 그 목록을 따른다.
- 예전 화면 코드는 새 규칙과 맞지 않아 지웠다. 랩탑 연출은 커밋 91f4467에서 다시 가져다 쓴다.

## 세션 4

### 요약
그림을 기다리는 동안 탑뷰 플레이 화면, 숙이기 단면, 휴대폰 카메라, 프롤로그 다섯 컷, 튜토리얼 손가락을 회색 상자로 만들었다.
빠듯 난이도로 여덟 판을 모두 실제 화면에서 클릭해 풀어 확인했다.

### 주요 변경
- `src/game.js`: 탑뷰 판, 메뉴판에 꺾이는 경로까지 보여 주는 조준선, 숙이기 단면과 줄 바꾸기, 카메라, 프롤로그, 튜토리얼, 랩탑 연출
- `src/assets.js`: 그림이 등록돼 있으면 그림을, 없으면 이름과 색이 있는 회색 상자를 그린다. 메뉴판 상자에는 기울기 대각선을 그린다
- `src/story.js`: 프롤로그 컷, 튜토리얼 혼잣말, 판 시작 혼잣말, 카메라 내용
- `src/levels.js`: 판마다 쓸 수 있는 도구(`tools`) 추가. 카메라는 4번 판, 숙이기는 7번 판부터 나온다
- `index.html`, `src/style.css` 새로 씀

### 결정 사항
- 탑뷰에서 줄 위에 마우스를 올리면 얼음 경로를 점선으로 미리 보여 준다. 메뉴판에서 꺾이는 것까지 보여서 규칙을 눈으로 익힐 수 있다.
  퍼즐의 핵심은 경로 계산이 아니라 거품 시점과 순서라서, 경로를 보여 줘도 답이 드러나지 않는다고 판단했다.
- 숙이면 탑뷰에서 마지막으로 가리키던 줄의 단면이 보이고, 위아래 버튼이나 화살표로 줄을 바꾼다.
- 진행 저장 키를 `magic-straw-progress-v2`로 바꿔 예전 프로토타입의 진행 기록과 섞이지 않게 했다.
- 프롤로그는 처음 한 번만 자동으로 나오고, 도움말에서 다시 볼 수 있다.

### 미해결 / 다음 할 일
- Codex에게 1차 그림 묶음 맡기기 (`docs/art-brief.md`). 그림을 등록하면 화면 코드 수정 없이 바로 바뀐다
- 프롤로그 컷이 넘어갈 때의 페이드 연출은 가려진 브라우저 탭에서 멈춰 보일 수 있다. 실제 화면에서 한 번 더 확인
- 실제 사람에게 플레이 테스트 (확인할 항목은 `docs/design.md` 마지막 절)
- 다음 수업: 2026-10-28 수요일

## 세션 5, Codex 그림 작업

### 요약
Codex가 프로젝트를 검토하고, 내장 image_gen으로 1차 그림 17개를 각각 생성했다.
Codex가 그림을 등록한 뒤 확인 페이지와 실제 플레이 화면에서 불러오는지 확인했다.

### 주요 변경
- `assets/top/`: 탑뷰 물건, 멀티탭 두 구간, 빈 테이블, 두 인물과 두 랩탑의 개별 PNG 12개를 저장했다.
- `assets/fx/`, `assets/ui/`: 거품과 얼음, 음료 두 종류와 손가락의 개별 PNG 5개를 저장했다.
- `assets/manifest.js`: 1차 그림 17개의 이름과 상대 경로를 등록했다.
- `assets/generation.json`: Codex가 사용한 생성 지시문을 기록했다 (원본 파일의 로컬 경로는 공개 저장소에 올리기 전에 Claude Code가 지웠다).
- `docs/project-review.md`, `docs/art-preview.png`: Codex가 최신 상태의 검토 기록과 실제 적용 화면을 저장했다.

### 결정 사항
Codex는 그림 의뢰서의 묶음 순서를 따랐다. Codex는 `src/`, 레벨, 목업을 수정하지 않았다.
그림 생성 중 Claude Code의 새 커밋이 들어왔고, Codex는 새 화면과 높이 조준 제한을 최종 검토에 반영했다.
생성 후 Codex는 투명 여백과 지정 크기만 정리했다. 각 물건을 합치거나 바닥 그림자를 그림에 넣지 않았다.
Codex는 17개 파일의 크기와 RGBA, 투명 영역, 개별 경로와 등록을 검사했고, 거품 중앙의 알파값이 0인지 확인했다.
최신 규칙 검사는 48개가 모두 통과했다. Codex는 여유 난이도로 여덟 판을 최소 행동 수에 풀고 마지막 판의 되돌리기도 확인했다.

### 미해결 / 다음 할 일
사용자가 이번 1차 그림의 시점과 그림체를 검토한 뒤, Codex가 옆면 10개와 프롤로그 다섯 컷을 이어서 만들 수 있다.
일부 그림에는 의뢰서보다 부드러운 명암이 남아 있고, 멀티탭 이음새에도 약한 색 차이가 있다.
화면 구현자는 첫 판 손가락이 빈 첫째 줄을 가리키는 동작과, 등록한 `fx-bubble` 대신 CSS 거품을 사용하는 부분을 검토해야 한다.
실제 사람이 처음 보는 상태로 플레이하는 테스트는 아직 하지 않았다.

그림과 문서는 저장했지만, Git이 .git/index.lock을 만들 때 권한 오류를 반환했다. Codex가 프로젝트와 .git 쓰기 권한을 요청해 받은 뒤에도 같은 오류가 발생해, 이번 그림 작업은 커밋하지 못한 상태로 남겼다.

### 결정 사항
- `.git` 폴더의 쓰기 금지는 Codex 샌드박스의 보안 장치라 풀지 않는다. Codex는 파일을 만들고, 커밋과 push는 Claude Code가 검토 뒤에 한다.
- 그림 PNG에는 텍스트 메타데이터가 없음을 확인하고 올렸다.

### 미해결 / 다음 할 일

- Codex가 2차(숙이기 시점) 10장과 3차(프롤로그) 5장을 이어서 만든다
- 실제 사람에게 플레이 테스트

## 세션 7

### 요약
사용자, Claude Code, Codex의 역할과 작업 순서를 `docs/workflow.md`에 정리하고, 데스크탑에서도 같은 방식으로 이어서 작업할 수 있게 준비했다.

### 주요 변경
- `docs/workflow.md`: 역할 표, 한 바퀴의 작업 흐름, 공개 저장소에 올리지 않는 것, 두 컴퓨터에서 작업하는 순서, 컴퓨터마다 따로 있는 것
- `AGENTS.md`: Codex는 커밋하지 않고 `.git` 권한도 요청하지 않으며, 세션 로그에 "커밋 대기" 목록을 남기고 멈춘다고 명시
- `CLAUDE.md`: 세션 시작 순서와 두 컴퓨터 공통 규칙을 앞으로 옮기고, 랩탑에만 맞던 문장(Node.js 없음, 로컬 경로)을 컴퓨터와 상관없게 고침
- `.gitattributes`: 저장소 안의 텍스트 파일을 LF로 통일

### 결정 사항
- 데스크탑에서는 처음 한 번 `git clone`으로 받고, 그 뒤로는 작업 시작 때마다 `git pull`, 끝날 때마다 push한다.
- 전역 지침은 컴퓨터마다 다르므로, 이 프로젝트에 꼭 필요한 규칙은 프로젝트 `CLAUDE.md`에 다시 적어 어느 컴퓨터에서든 같게 적용되게 했다.
- 게임 허브 등록은 게임이 완성되고 사용자가 허락하면 데스크탑에서 한다.

### 미해결 / 다음 할 일
